# 工程スケッチ 設計メモ(汎用シミュレーターとの比較と取捨選択)

## 1. 参照した汎用シミュレーターの考え方
- **Tecnomatix Plant Simulation**(Siemens, 公開入門資料 "Introduction to Tecnomatix Plant Simulation" 2201)
  - 物の流れのオブジェクト: Source / Station / Buffer(容量) / Assembly(Container へ積む) / Conveyor / Drain、Connector でつなぐ
  - 設備のタブ: Times(加工時間・分布) / Set-Up(段取り) / Failures(故障・休止) / Controls(制御) / Exit(払い出し戦略: Percentage 等)
  - 状態統計: Working / Setting-up / Waiting / Blocked / Powering / Failed / Stopped / Paused / Unplanned
  - 結果: Chart(状態の積み上げ棒)・SankeyDiagram(流量の太さ)・HtmlReport(スループット/時・平均滞留)。EventController で終了時刻・統計開始時刻(ウォームアップ)
  - DataTable で品種構成、Frame の階層化と継承
- **FlexSim**(Autodesk)
  - 固定資源(Source / Queue / Processor / Combiner / Separator / Sink)と 移動資源(Operator / Transporter / AGV = Task Executer)の二分
  - Processor の「加工/段取りに作業者を使う」、Dispatcher による作業者の割り当て
  - Time Table(シフト・休憩)、MTBF/MTTR(故障)、Down Behavior
  - Experimenter(シナリオ比較・反復・ウォームアップ)、Dashboard(状態の円グラフ・スループット・滞留)、A* による障害物回避
  - ドラッグ&ドロップ+プロパティ画面で、コードなしで組める

## 2. 工程スケッチとの比較と判断(LexxMoMa の対象工程に特化)
LexxMoMa(自律移動+協働アーム)が入るのは「設備への投入・取り出し(マシンテンディング)」と「工程間の運搬」。
営業の場で決め手になるのは **「1日に何個できるか/必要数に届くか」「人の時間がどれだけ空くか」「LexxMoMa に何を任せると何が変わるか」**。

| 汎用ツールの要素 | 工程スケッチ(改善前) | LexxMoMa の商談での重要度 | 判断 |
|---|---|---|---|
| シフト・休憩(Time Table / ShiftCalendar) | なし | 高: 人は休憩で止まる/ロボットは止まらない、が価値の核 | **採用**: 1日の稼働時間+人の休憩(1つの値) |
| 故障・可動率(MTBF/MTTR, Failures) | なし | 中: LexxMoMa の充電分だけは効く | **一部採用**: LexxMoMa の稼働率[%]だけ。設備の故障は数字が無いので不採用 |
| ウォームアップ(統計開始時刻) | なし(立ち上がりを含む) | 高: 結果の正しさ | **採用**(画面には出さない。20分空回ししてから測る) |
| シナリオ比較(Experimenter) | 前回比のみ | 高: Before/After が営業の話の筋 | **採用**: 「現状」を残して比較(2案のみ) |
| 必要数・タクト | なし | 高: 顧客が最初に言う数字 | **採用**: 必要数/日 → タクト・達成/不足 |
| 作業者に設備作業をさせる(use operator for process) | あり(人の作業時間) | 高 | 維持。LexxMoMa にも割り当てられる |
| 運搬係(Task Executer)・A* | あり | 高 | 維持 |
| 状態統計 | あり(自動/人/人待ち/材料待ち/詰まり) | 高 | 維持(平易な日本語) |
| 入れ物(Container) | あり(TPポリ箱の通い箱運用) | 高 | 維持 |
| LexxMoMa に任せる作業の選択 | 運搬の1本ずつのみ | 高: 設備作業も任せたい | **採用**: 運搬+設備作業を選んで一括で比較 |
| 分布(ばらつき)・反復 | なし | 低: 営業段階は平均値で十分、説明しやすさ優先 | 不採用 |
| 段取り替え | なし | 低〜中 | 不採用(人の作業時間に含めて入力) |
| 品種構成(DataTable) | なし | 低 | 不採用 |
| 払い出し戦略(Percentage 等)・作業者プール | 暗黙 | 低〜中 | 不採用(担当を明示した方が説明しやすい) |
| Sankey / Gantt | 矢印・表 | 中 | 不採用(矢印+回数で代替) |
| コスト・エネルギー | ROI ツール | — | 不採用(ROI 簡易計算ツールへ) |
| 階層化・継承 | なし | 低 | 不採用(複製で代替) |

## 3. 改善の繰り返し(要素の追加 → 複雑さの評価 → 簡素化)
各回の記録は下に追記する。

### 第1回: 最小限の追加
- 1日の条件(稼働時間・人の休憩・必要数・LexxMoMa の稼働率)を「はじめ方」の下に置く
- 「1日分を計算」: 20分空回し → 1時間測る(人がいる時)+ 休憩中(人がいない時)も1時間測る → 1日に換算
- 結果の最初に「1日にできる数/必要数」「人の作業時間/日」
- 「現状」を残して比べる、「LexxMoMa に任せる作業を選ぶ」
- 実装後の確認(2台・並行作業セルのひな形): 材料の払い出し間隔で頭打ちになる。上位の作業(設備へのセット)を LexxMoMa に任せると、人の作業時間が減ることを確認
- 見つかった不足: 全体の速さを決めているものが「材料が入ってくる速さ」のとき、利用率が一番高い作業者と誤表示 → Source 律速の判定を追加(汎用ツールでいう入力律速)

### 第2回: 複雑になった分の簡素化
第1回を終えた画面の評価: 部品17種・左に設定が続く・図の上に時間カード・「1日分を計算」が2行目・右パネルに寸法や面の欄が並ぶ。
- パレットを4群・15種に(手作業台=加工+人の作業時間、色分けエリア=メモ で代わりになるので非表示。古いデータは読める)
- エリア・通路・下絵の設定は「図の設定」にたたむ
- 図の上の「工程の時間」カードを廃止し、はじめ方の欄と結果に移す(図を広く使う)
- 下の帯は「1日分を計算」を先頭・大きく、動きを見る▶は二番手
- 右パネル: 寸法・位置・出し入れ面・歩く速さ・積み降ろし・向きは「詳しい設定」にたたむ。常に見えるのは名前と工程カードだけ
- 結果: 結論(1日の数・必要数との判定・人の時間)→ 比較 → LexxMoMa → 「詳しく見る」(従来の表はここにたたむ)

### 第3回: 営業メンバーの操作をなぞって、つまずきを潰す
操作: 使い方の窓 → ひな形 → 加工の時間を直す → 計算 → 必要数を入れて再計算 → LexxMoMa に任せる → 検討シート
- つまずき1: 計算後に設備をクリックしても右は「結果」のまま → 選んだら「設定」へ自動で切り替え
- つまずき2: 必要数が「何も選んでいない時」の欄にしかない → 結果の上に1日の条件の小さな入力欄と「この条件で計算」
- つまずき3: 任せた後に何を任せたか分からない → 結果に「LexxMoMa1 に任せている作業」
- つまずき4: 最初にひな形を探す手間 → 使い方の窓からひな形を1クリックで選べる
- つまずき5: LexxMoMa の前提(走行速度・積み降ろし秒)が結果を大きく左右するのに見えない → 選ぶ欄に前提を明記
- なぞった結果: 7操作で「必要数 500個に 192個 足りない」→ LexxMoMa 案で「人の時間 -3.8時間/日・1日 -14個」まで到達(積み降ろし20秒の前提が効いていることが分かる)

### 最終の構成(営業が触るのはここだけ)
1. 左: 置く(4群15種)  2. 図: つなぐ・面をドラッグ  3. 右: 名前と工程カード(入れる/出す/時間)
4. 下: 「1日分を計算」  5. 結果: 1日の数・判定・人の時間 → LexxMoMa に任せる → 比較 → 検討シート
それ以外(寸法・面・速さ・通路・下絵・詳しい表)はすべてたたんである。
