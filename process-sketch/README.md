# 工程スケッチ

ベータ版として公開。レイアウトと人・モノの流れを検討できます。

営業・お客さまが1分で工程レイアウトを描き、作業者がモノを運ぶ導線を動かして共有するツール。
配布物は `dist/process-sketch.html`(単一HTML・オフライン動作・外部送信なし。`../../assets/track.js` だけは任意の利用計測)。

## 構成
- `src/core.js` … カタログ(部品の種類と初期値)、経路探索(250mmグリッドA*+平滑化)、導線シミュレーション `PS.Sim`(DOM非依存)
- `src/ui.js` … SVG描画・操作・パネル・ひな形・保存/共有URL・下絵(縮尺合わせ)
- `src/report.js` … 書き出し: PNG(100px/m=2D動作シミュレーターの背景縮尺)、CSV、検討シート(印刷用HTML、図面データ埋め込み→「開く」で再編集可)
- `src/onboarding.js` … 使い方ガイド(「?」の窓・右パネルの「初めての方へ」から開く)。図のデータは変えず、選択・タブ・表示範囲だけ動かす(`PSUI.select / switchTab / fit`)
  - 画面の見かた: 6つの領域(部品/図の道具/工程の図/設定と結果/計算と再生/右上のボタン)に番号と説明を重ねる
  - 操作ツアー(6手順): 対象をスポットライトで示し、吹き出しを横に出す。操作を検知すると「✓ できました」→自動で次へ。必要な準備(設備を選ぶ・計算する)はツアー側で行う。「代わりにやる」「とばす」あり
  - やりたいことから探す: 10項目。押すとその操作をする場所だけを示す
- ビルド: `python build.py` → `dist/process-sketch.html`

## モデル(簡易)
- 設備: 加工 A→B / 溶接・接着・組立 A+B→C(入る矢印ごとに決めた数だけ待つ) / 検査 A=A(NG率) / 手作業台 / 仮置き(容量)
- 工程カード(設備を選ぶと右に出る): ① 前工程とモノの名前・1回に使う数(`inQty`) ② 出すモノの名前・1回で出来る数(`outQty`)と次工程 ③ 時間=自動運転 `autoT` + 人の作業 `manT`
- 1サイクル = 人の作業(作業者が作業面の前にいる間だけ進む) → 自動運転(人は離れてよい)。`manT>0` なら needOp。旧形式の ct/needOp は `PS.migrateObj` で変換
- 並行作業(`parallel`, `swapT`): 自動運転中に人が次のワークのセット・取り出しを同時に進められる設備(ワークを置く場所が2つある: 回転テーブル・シャトル・パレットチェンジャー等)。両方終わるとワークを入れ替える。1回 = max(自動, 人) + 入れ替え時間。旧データの rotary/indexT は読み込み時に変換
- 用語の方針: 機能名・画面の言葉は一般化した表現にする。特定の設備・工程の仕組みの名前(反転治具など)を機能名にしない。ひな形の中身は例として具体的でよい
- 開口の幅(`portW` mm): 出し入れ口の描画幅。空欄なら自動
- ひな形「2台持ちセル(並行作業)」: 並行作業・仮置き・台車出荷を一通り試せる一般的なサンプル(搬入コンベヤ → 仮置台 → 組立機×2 → 検査 → 台車で出荷)。設備名・寸法・時間はすべて例の値。ひな形は実在の顧客工程に似せない
- 工程の時間: 一番長い設備・1個が通る設備の時間(最長ルート, `PS.timeSummary`)・シミュ後の完成の間隔と リードタイム(仕掛の時間平均÷完成の割合=リトルの法則、概算)
- 出し入れ面は図の上の 入/出/足あと をドラッグして別の面で離すと変わる
- 入れる面=取り出す面 かつ その面が 1500mm 以下(`PS.SHARE_LEN`)なら「出し入れ口」1つにまとめる(`PS.sharedPort`): 印は▼▲+「入出」、立ち位置も1か所、待ち/出来たモノは口の左右に並ぶ。口のドラッグで入・出が一緒に動き、Shift+ドラッグで「出」だけ移せる
- 大きい設備でも、「出」を「入」の上へドラッグして重ねるとまとまる(`o.portShared=true`、分けると false)。印は面の上の好きな位置へ動かせる(`o.portOff[役割]`=面の中心からの mm。面に沿う向きは tangent=(-ny,nx): N面は右が+、S面は左が+)
- 再生中・停止後でもモノをクリックすればシミュレーションを終えて選べる(結果パネルは残す)
- 運搬: 矢印ごとに運び手(作業者 or LexxMoMa)と運び方(手運び n個 / 台車・コンテナ=取りに行って押して運び、置いて帰る / 自動)
- 人の優先順: 担当設備の作業 > 詰まった設備の払い出し > 材料切れ設備への供給 > たまり具合。無限の搬入口は低優先(引き取り)
- LexxMoMa 初期値: 750×600mm、1.0 m/s、積み降ろし20秒(案件ごとに要確認)
- 出し入れ面(ポート): 設備ごとに 入れる面/取り出す面/作業する面(上下左右)。「自動」はつないだ相手・付く作業者の方向へ向く(`PS.autoOrient`)。作業者は面の正面 500mm(`PS.STAND`)に立ち、面に正対して作業
- 体の向き: 目標方向と35°以上ずれるとその場で向きを変えてから歩く(人 240°/s・台車押し 90°/s・LexxMoMa 180°/s)。向き替え時間は結果に「分/時」で出る
- 台車は体の前に押し、設備の前では横に置く。コンテナは抱える
- 通路(多角形, type walk): `doc.walkOnly`(既定 true)なら人・ロボットは通路の中だけ通る(通路が無いときは警告してどこでも歩ける扱い)。ひな形には通路入り。立入禁止(多角形)の中は通らない。立ち位置がエリア外なら確認事項に警告
- 段取り替え・休憩・故障は含まない

## 1日の計算と比較(汎用シミュレーターとの比較から採用。経緯は DESIGN.md)
- 1日の条件 `doc.day`: 稼働時間・人の休憩(分)・必要数(個/日)・LexxMoMa の稼働率(%, 充電などを除く)。`PS.dayOf`
- `PS.simulateDay`: 20分空回し(立ち上がりを除く)→1時間測る。休憩がある時は「人がいない状態」も別に1時間測って1日に換算。LexxMoMa は30分ごとに稼働率の残りだけ持ち場で充電
- 全体の速さを決めているもの: 利用率が一番高い設備/人。ただし材料の入ってくる速さで頭打ちなら「材料が入ってくる速さ」
- 比較: `doc.baseline`(名前・要約 `PS.dayMetrics`・その時の図)。「現状として残す」「現状の図に戻す」「比較をやめる」
- LexxMoMa に任せる作業: 人が担当する運搬と設備の作業を「人の時間が長い順」に並べ、選んだものを LexxMoMa に割り当てて再計算(無ければ1台置く)

## 見た目のルール
- 運ぶモノ(部品)と入れ物(TPポリ箱)は別々に扱う。部品の種類(`PS.PACKS`): 樹脂部品=黒いアーチ形の成形品 / 金属部品=銀色の穴あきブラケット。搬入口・部品置き場の「部品の種類」、工程カード②の「部品の種類」(空欄=前工程と同じ)で決める。段ボールの絵は使わない
- TPポリ箱は通い箱(type `container`、容量 cap=入る部品の数)。流れの運び方で選ぶと: 取り出す側に置いた空き箱へ出来た部品が溜まる(`fillBoxes`)→ 満杯で箱ごと入れる側へ届ける → 設備は箱から1個ずつ使う(`inAvail`/`take`)→ 空になった箱を取り出す側へ戻す。1つの流れで複数の箱を使える(`f.mover` + `f.movers`)。箱には中身「3/10」「空」を表示。搬出口・仮置きへ届けた箱は中身をそのまま渡して空になる。置き場の「TPポリ箱に入れて置いてある」(`boxed`)は見た目だけ
- 並行作業の時間表示は「自動◯秒・人◯秒は同時 → 長い方◯秒 + 入替◯秒 = ◯秒」(足し算が合う書き方にする)
- 色は機能で分ける(`PS.FN`): 加工=青 / 検査=灰青 / 停滞(仮置き・部品置き場)=灰 / 運搬(台車・コンテナ・LexxMoMa)=緑 / 人=橙(複数人は濃淡) / モノ=黄土 / 出入口=灰。新しい部品は CAT に `fn` を付けて色はここから取る
- 設備は角を丸めない(直角)
- 再生中: 入れる面の内側に待っているモノ、取り出す面の内側に出来たモノ(検査済みは✓)を箱で並べる。加工中は設備の角に箱+進み具合の輪(人=橙/自動=青)。運搬中の流れは矢印上を点線が流れる。搬出口には完成品が積み上がる

## 計算と出力の整合性（2026-09-29更新）
- 1日計算はウォームアップ換算を廃止し、始業から終業まで連続実行。休憩は勤務時間の中央に置き、在庫・作業・箱を保持する。
- 到達不能の運搬はその位置で停止し、後続の投入・取り出しも実行しない。通路必須で通路が未設定なら移動不可。
- 検討シートとCSVは出力直前に再計算。比較用の現状データは維持する。
- 回帰確認: node --test test/continuity.test.cjs
